# ipmesctool

基于 Tauri 2、React 和 Rust 的电机配置与调试工具，串口协议对齐 GPMD_Code 的 `APP/uart_com.cpp`。

## 开发与验证

```sh
bun install
bun run dev          # 前端，端口 1420
bun run tauri dev    # 完整桌面应用
bun run build        # TypeScript 检查与前端构建
cargo test --manifest-path src-tauri/Cargo.toml --lib
```

## 串口交互

- 连接使用 460800 baud，先发送 `get_none` 停止遗留数据流，再执行 `get_config` 校验设备与配置格式。普通命令以 CRLF 结束，必须收到 `ok` 才确认成功；`error parameter/state/flash/internal/command` 会显示具体原因。下述数据流切换命令没有应答，仅确认主机已写出。
- 配置快照包含固件状态、uint32 设备 ID、Rs/Ld/Lq、电流/速度/位置环参数、速度环辨识扫频电流幅值及编码器配置。读取等待末尾 `ok`，缺字段不会被当作成功。
- 配置写入仅允许 `Ready` 状态，固件自动写 Flash，无需独立保存。设备 ID 写入范围为 **0–2047**（标准 FDCAN ID），不是整个 uint32 范围。电流 PI 写入只有一组共用 `kp/ki`，同时覆盖 d/q；校准后的 d/q 读回值可能不同。速度环辨识扫频电流 `config_speed_sweep_current` 使用 q 轴正弦幅值（A），必须大于 0，默认 0.5 A。
- 编码器支持 `AS5600`、`MT6701_IIC`、`MT6701_SPI`、`AS5047P`，方向 `CW/CCW`，极对数 1–255，偏移为电角度 rad。
- 控制支持速度（rpm）、累计机械位置（度）、q 轴电流（A）、停止，以及 `Fault` 状态下清除故障。界面选择 rad/s 或 rad 时会换算为固件所需单位。
- 校准启动的 `ok` 不代表完成；工具持续读取阶段、结果及失败阶段，直到终态报告结束。成功后由固件主循环自动保存参数；协议没有独立的保存结果应答。
- 串口控制台可以发送单行原始命令，并保留最新 5000 行 TX/RX。普通命令与应答串行处理；超时或普通应答接收丢行时关闭连接，避免迟到应答错配下一条命令。连续流不占用普通应答通道。

当前固件 UART 不提供母线电压设置、电流滤波设置或电机电气参数手动写入；这些入口与手动保存功能仍不提供。

## 波形图

在侧栏打开“波形图”，选择采集模式并点击“开始采集”。四种模式互斥，采集中切换选择会切换固件连续输出：

| 模式 | 命令 | 帧格式 | 单位 |
|---|---|---|---|
| 三相电流 | `get_iabc` | `iabc:a,b,c` | A |
| DQ 轴电流 | `get_idq` | `idq:d,q` | A |
| 机械速度 | `get_speed` | `speed:给定,反馈` | rpm，界面可切换 rad/s |
| 累计机械位置 | `get_position` | `position:给定,反馈` | deg，界面可切换 rad |

- “停止采集”只发送 `get_none`，**不会停止电机**；停机仍使用底部 `Stop`。上述五个流控制命令都没有 `ok`，页面显示的是主机写出状态，不是固件确认；串口控制台发送这些命令也遵循同一规则。
- 固件最多按 1 kHz 节拍输出。横轴为本次连接的**主机单调接收时间**，不是设备采样时间；UART 带宽和调度会影响实际间隔。
- 图表支持 1/5/10 秒时间窗。“暂停查看”冻结当前快照，采集仍在继续，可拖动历史滑块；“跟随最新”恢复实时查看。“清空全部波形”清除四种模式的历史，不停止采集。
- 每模式最多保留 10000 点；后端待发队列最多 256 点、约每 33 ms 批量送往前端。消费不及时会淘汰最旧波形点，不影响普通命令应答。断开连接会停止采集并清空波形；连接关闭前尽力发送 `get_none`。


协议回归测试覆盖配置字段/数值边界、校准终态与失败报告、控制状态限制、应答识别、四种波形帧解析及高频流与应答隔离。PTY 模拟串口可以验证主机读写路径，但不能替代真实电机的控制、波形时序与校准验收。
